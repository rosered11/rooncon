## บทเรียน: คำที่เปิดช่องให้โมเดลไประบายสี

สองบรรทัดนี้ทำให้ **1 ใน 3 ของภาพหลุดกรอบ** กลายเป็นภาพวาดมีเทกซ์เจอร์:

```
- Slight paper grain over flat color areas
- Occasional light tonal shading inside objects
```

คำว่า *grain* *shading* *texture* คือใบอนุญาต พอเจอคำบรรยายฉากอย่าง savanna หรือ highway มันจะวาดเต็มรูปแบบ **ลบทิ้ง** — บทเรียนนี้ยังใช้ได้แม้พื้นหลังจะมีสองโซนตาม V4 ก็ตาม เพราะแต่ละโซนยังต้องเป็นสีเรียบ ไม่ใช่ภาพวาดมีพื้นผิว

## FORBIDDEN ที่ต้องมี

```
- Painted or illustrated backgrounds within each flat-color zone
- Grass texture, cloud shading, ground detail, atmospheric perspective
- Realistic humans — every person is a STICK FIGURE with no exceptions
- Muscles, clothing folds, hair strands, teeth, nose shading
- Gradients, drop shadows, glows, textures of any kind
- Thai text rendered anywhere in the image
- NEVER render @tags, filenames, or shot numbers as visible text in the image
```

## [RULES] ที่ต้องมีทุก batch (นอกเหนือจาก FORBIDDEN ด้านบน)

```
- Keep character appearance IDENTICAL across all shots — follow CHARACTER BIBLE exactly
- On-screen text allowed ONLY where written in the shot line, ALL CAPS English
- Aspect ratio 16:9 for ALL images, highest resolution available
- Muted palette only — no saturated primaries, no thick marker lines
```

## ย้ำสไตล์ท้ายทุกบรรทัด shot

```
| Style: flat vector stick-figure, thin consistent ink line, muted earth palette, background split by horizon line (NOT single solid color) | Characters per CHARACTER BIBLE
```

ย้ำทุกช็อตกัน drift ได้ดีกว่าเขียนไว้ครั้งเดียวข้างบน

## บทเรียน: "@name icon" (ติดกัน) ทำให้โมเดลวาด "@" เป็นรูปสัญลักษณ์แทนตัวละคร

ตอน regen รอบ 44 ใบของคลิป 002 เจอต้นตอที่แก้ได้จริงในตัว prompt เอง: shot ที่เขียนว่า `@duck icon` หรือ `@duck stick-style icon` (มี @ ติดกับคำว่า icon ตรง ๆ) ทำให้โมเดลตีความ "@" เป็นรูปทรงมาแทนที่ตัวเป็ดทั้งตัว ไม่ใช่แค่คำสั่งเรียกตัวละคร

## บทเรียน: ข้อความในวงเล็บ/hex code ใน prompt เสี่ยงถูกวาดเป็นตัวหนังสือบนภาพ

พบสองรูปแบบที่ทำให้ตัวหนังสือหลุดเข้าไปในภาพ นอกเหนือจาก @tag:
- **วงเล็บอธิบายเสริมสำหรับคน/agent อ่าน** เช่น `crossed-out dice icon (not random)` — โมเดลวาดทั้งวงเล็บเป็นแคปชันบนภาพ ห้ามใส่ note แบบนี้ปนกับคำบรรยายภาพ ถ้าต้องอธิบายเหตุผลให้เขียนแยกไว้นอก prompt
- **โค้ดสี hex ในหัวข้อ Style Bible** เช่น `#D94040` — แม้จะตั้งใจไว้ใช้อ้างอิงภายในเท่านั้น โมเดลบางครั้งก็หยิบไปวาดเป็นตัวหนังสือแดงบนภาพจริง (เกิดกับ SHOT 13) แก้โดยเขียนพาเลตต์เป็นชื่อสี (เช่น "muted teal-green") ในพรอมป์ที่ส่งจริง แล้วเก็บโค้ด hex ไว้เฉพาะในเอกสารอ้างอิงของทีม (`images.md` นี้) เท่านั้น อย่าเอา hex ใส่ในพรอมป์ที่จะส่งเข้า Flow ตรง ๆ

## บทเรียน: "same as shot X" ไม่ใช่แค่ไม่การันตีตรง — ควรเลี่ยงเขียนแบบนี้ตั้งแต่แรก

ต่อยอดจากบทเรียนก่อนหน้า (prompt "same as shot X" ไม่การันตีเนื้อหาตรง) — วิธีแก้ที่ดีกว่าการเปิดดูเทียบทุกใบคือ **เขียนคำบรรยายเต็มแบบ standalone ทุกช็อตตั้งแต่ตอนสร้าง shot list** ไม่อ้างอิงข้ามช็อตเลย แม้จะยาวกว่าเล็กน้อย เพราะ Google Flow ไม่มี context ผูกระหว่างช็อตต่างกัน (คนละ generation call) การอ้างอิง "same as shot 1" จึงเป็นข้อมูลที่โมเดลไม่มีทางรู้จริง ๆ

## บทเรียน: ฉาก ocean/dolphin (และฉากธรรมชาติทั่วไป) ต้องใส่ anti-realism reminder ซ้ำทุกช็อตเป็นพิเศษ

บล็อกฉากโลมา (SHOT 60–82) หลุดสไตล์เป็น photorealistic ทั้งบล็อกแม้จะมีคำว่า "flat"/"icon" อยู่ใน prompt เดิมแล้ว — คำเดี่ยว ๆ ไม่พอกันเนื้อหา ocean/animal ที่โมเดลถูกเทรนมาให้วาดสมจริงเป็นค่าเริ่มต้น
**วิธีที่ใช้แก้ตอน regen:** เติมบรรทัดย้ำท้ายทุกช็อตในฉากธรรมชาติโดยเฉพาะ (ไม่ใช่แค่ suffix มาตรฐาน) เช่น `REMINDER: flat vector icon, NOT a nature photo — solid flat ocean/sky, no gradient, no sunset, no realistic water, no eye highlights` — แรงกว่าคำย้ำสไตล์ปกติ เพราะฉากนี้มีแนวโน้มหลุดสูงกว่าฉาก interior/icon ทั่วไป
