# เสียง

## ค่าเป้าหมาย

-14 ถึง -16 LUFS · LRA 2–3 · true peak ไม่เกิน -1.0 dBFS · แซมเปิลชนเพดาน 0

YouTube **หรี่คลิปที่ดังเกิน แต่ไม่ดันคลิปที่เบาให้ดังขึ้น** ส่งไปเบา = เสียเปรียบถาวร

## เชนที่ใช้จริงและผ่าน

```
volume=-3dB, alimiter=limit=0.891:level=disabled,
loudnorm=I=-14:TP=-1.2:LRA=3, alimiter=limit=0.85:level=disabled
```

ผลลัพธ์: -15.3 LUFS · LRA 2.2 · true peak -1.33 dBFS · clipped 0

**ที่มา:** `ElevenLabs_custom_v2_fixed.wav`
**วันที่:** 2026-08-06

## บทเรียน: alimiter ต้องมี level=disabled

ถ้าไม่ใส่ ตัวลิมิตจะดันความดังกลับขึ้นมาจน peak ทะลุอีก เสียเวลาไปหลายรอบกว่าจะเจอ

## บทเรียน: Limiter ต้องเป็นขั้นสุดท้ายเสมอ

เคยใช้ **Amplify** แทน Limiter หลัง Loudness Normalization ใน Audacity
ผล: true peak +0.29 dBFS · 4,164 แซมเปิลชนเพดาน กระจาย 2,051 ช่วง = เสียงแตกจริง

**ห้ามใช้ Amplify แทน Limiter เด็ดขาด**

**วันที่:** 2026-08-06

## ElevenLabs ทำ mastering ให้ไม่ได้

ไม่มี compressor ไม่มี limiter ไม่มีที่ตั้ง LUFS ทุกแพลน ส่งออกมาราว -23.5 LUFS คงที่
ต้องมาสเตอร์นอกเครื่องมือเสมอ ไม่มีทางลัด

v3 คือโมเดลเดียวที่รองรับไทย · ไม่รองรับ `<break>` tag · ช่อง TTS จำกัด 5,000 ตัวอักษร

## ช่วงหยุดที่เหมาะ

เฉลี่ย 0.33–0.40 วินาที · ยาวสุดไม่เกิน 0.95 วินาที
ช่วงที่ยาวเกิน 1 วินาทีคือรอยต่อบท **ห้ามตัดให้เท่ากับช่วงอื่น** ไม่งั้นฟังเหมือนอ่านรวดไม่มีวรรคตอน

## เตรียมเสียงตัวอย่างสำหรับ train voice clone — ต่างจาก mastering เสียงพากย์ปกติ

โจทย์ "เอาไฟล์เสียงที่อัดเองไปเทรนเป็นเสียงพากย์" (เช่นฟีเจอร์ voice cloning ของ ElevenLabs) มีเป้าหมายคนละแบบกับ mastering เสียงพากย์ไปลง YouTube — **ห้ามใช้เชนเดียวกัน**:

| | mastering เสียงพากย์ (YouTube) | เสียงตัวอย่าง train voice clone |
|---|---|---|
| เป้า LUFS | ‑14 ถึง ‑16 (ดังเต็มมาตรฐานแพลตฟอร์ม) | **‑20 LUFS** พอ — ไฟล์นี้ไม่ได้เผยแพร่ตรง ๆ ต้องการ headroom ธรรมชาติมากกว่า |
| Dynamics | บีบด้วย limiter หนัก ท้ายเชนเสมอ | compressor **เบา ๆ** เท่านั้น (~2.3:1) กัน "ความรู้สึก"/อารมณ์เสียงหายไป ห้ามบีบจนแบน |
| ช่วงเงียบ | ตัด mid-roll เท่านั้น ไม่แตะช่วงหยุดพูด | **ต้องหดช่วงเงียบทุกจุดเพื่อคุมความยาว/ขนาดไฟล์** โดยไม่ตัดคำพูดทิ้งแม้แต่คำเดียว |

**วิธีหดช่วงเงียบแบบไม่ตัดคำ:** รัน `ffmpeg silencedetect` หาทุกจุดเงียบ (noise=‑35dB, d=0.3) แล้วเก็บเฉพาะ **ช่วงต้น** ของความเงียบเดิมมาแทนความเงียบทั้งก้อน (ไม่ใช้ความเงียบดิจิทัลล้วน จะได้รูมโทนธรรมชาติ ไม่รู้สึกตัดแปะ) — cap ตามกฎเดียวกับ TTS breaks ด้านบน: ช่วงหยุดสั้น (<1s) เหลือ 0.25s, ช่วงหยุดยาว/รอยต่อประโยค (≥1s) เหลือ 0.55s, ช่วงเงียบนำหน้าไฟล์ (ก่อนคำแรก) เหลือ 0.10s เท่านั้น

**เชนที่ใช้จริงและผ่าน** (หลังหดช่วงเงียบแล้ว):
```
highpass=f=70, afftdn=nf=-40,
acompressor=threshold=-24dB:ratio=2.3:attack=15:release=220:makeup=2,
equalizer=f=3000:t=q:w=1.2:g=1.5, equalizer=f=9000:t=q:w=1:g=1.5,
loudnorm=I=-20:TP=-1.5:LRA=6 (two-pass, linear=true),
alimiter=limit=0.891:level=disabled
```
ผลลัพธ์จริง: ต้นทาง ‑31.1 LUFS / 150.1s / 13.2MB → ปลายทาง ‑20.04 LUFS / true peak ‑1.5dBTP / 0 clipped / **1:56.2 / 9.77MB** (โจทย์: ไม่เกิน 2 นาที ไม่เกิน 10MB)

**ทำไมต้องคุมขนาดไฟล์แบบนี้:** WAV 16-bit 44.1kHz mono กินพื้นที่ตรงตัว ~88,200 ไบต์/วินาที เพดาน 10MB จึงเทียบเท่า **~118.9 วินาทีเป๊ะ** — ต้องเผื่อ margin ให้เหลือ ~115s ไม่ใช่กะตัดที่ 120s พอดี เพราะจะดันไฟล์ทะลุ 10MB

**วันที่:** 2026-08-08
