# CapCut Edit — ประกอบคลิปในไทม์ไลน์จากไฟล์ที่ไปป์ไลน์เตรียมไว้

เอาเสียงมาสเตอร์ + ภาพ 213 ช็อต + ซับ + BGM + end credit มาประกอบเป็นโปรเจกต์ CapCut พร้อม export
ทำงานด้วยการแก้ไฟล์โปรเจกต์ CapCut ตรง ๆ (`draft_info.json`) เพราะเร็วกว่าลากทีละช็อตในแอปมาก แต่ไฟล์นี้เป็นฟอร์แมตปิด ไม่มีเอกสารทางการ — **ต้องเรียนรู้โครงสร้างจาก draft ที่ทำสำเร็จแล้วจริงทุกครั้ง ห้ามเดา schema เอง**

---

## 🔒 กฎเหล็กข้อเดียวที่พลาดไม่ได้เลย — เช็คก่อนแตะไฟล์ทุกครั้ง

```bash
ps aux | grep -i capcut | grep -v grep
```

**ต้องได้ผลลัพธ์ว่างเปล่าเท่านั้นถึงจะแก้ไฟล์ได้** ถ้า CapCut เปิดโปรเจกต์นั้นค้างอยู่ (เห็น process ใน `ps aux`) แล้วแก้ `draft_info.json` ด้วยสคริปต์ — พอโปรแกรม autosave มันจะเขียนทับไฟล์ด้วยข้อมูลในหน่วยความจำของตัวเอง (ที่ไม่มีการแก้ไขที่เพิ่งทำ) ทับทุกอย่างที่เพิ่งเขียนไปจนหายสนิท เคยเจอมาแล้วจริงกับ track BGM ที่เพิ่งเพิ่มหายไปทั้ง track

**ขั้นตอนที่ถูกต้อง:**
1. บอกผู้ใช้ให้ **ปิด CapCut ให้สนิทก่อนเริ่ม** (Quit ทั้งแอป ไม่ใช่แค่ปิดหน้าต่างโปรเจกต์)
2. เช็ค `ps aux` ยืนยันว่าไม่มี process เหลือ
3. แก้ไฟล์
4. ยืนยันว่าไฟล์ยัง parse เป็น JSON ได้ถูกต้อง (ดูขั้นตอน "ตรวจก่อนส่งมอบ" ด้านล่าง)
5. **บอกผู้ใช้ว่าตอนนี้เปิด CapCut ได้แล้ว** — ห้ามให้เปิดก่อนขั้นตอนนี้เสร็จ

หา UUID ของ Timelines ด้วย:
```bash

```

## วิธีที่ปลอดภัยที่สุด: โคลนโปรเจกต์ที่ทำสำเร็จแล้วมาเป็นแม่แบบ แทนสร้างจากศูนย์

**อย่าพยายามประกอบ `draft_info.json` ขึ้นมาใหม่ทั้งดุ้นจากความว่างเปล่า** ฟอร์แมตซับซ้อนและไม่มีเอกสาร เสี่ยงพังทั้งโปรเจกต์ วิธีที่ใช้ได้จริงและปลอดภัยกว่ามาก:

1. เลือกโปรเจกต์เก่าที่ทำสำเร็จแล้วจริงเป็นแม่แบบ (เช่น `002_first_night_sleep` หรือ `0807`) — โครงสร้าง track/effect/BGM/end-credit ที่ต้องการมีอยู่แล้วในนั้น
2. **คัดลอกทั้งโฟลเดอร์โปรเจกต์** ไปเป็นโปรเจกต์ใหม่ของคลิปนี้ (ตั้งชื่อให้สื่อ เช่น `003_giraffe_neck`) ก่อนแก้อะไรทั้งสิ้น
3. อ่าน `draft_info.json` ของแม่แบบด้วย `jq` (ไม่ใช่ Read ตรง ๆ เพราะไฟล์ใหญ่ ~1.4MB) เพื่อเรียนรู้โครงสร้างจริงก่อนแก้ เช่น:
   ```bash
   jq '.tracks[] | {type, id}' draft_info.json
   jq '.materials.videos[0]' draft_info.json      # โครงสร้าง 1 รายการภาพ
   jq '.materials.audios[0]' draft_info.json      # โครงสร้าง 1 รายการเสียง
   jq '.tracks[] | select(.type=="text")' draft_info.json  # โครงสร้างซับ
   ```
4. เขียนสคริปต์ python (ใช้ `json.load` / `json.dump`, ห้ามแก้ text ด้วย string replace เพราะ escape พัง) ที่:
   - ลบ segment ของภาพ/เสียง/ซับเก่าออกจาก track เดิม
   - สร้าง segment ใหม่ตามข้อมูลของคลิปนี้ โดยคัดลอกโครงสร้าง key ทุกตัวจาก segment ตัวอย่างที่อ่านมาได้ในข้อ 3 มาเป็นแม่แบบ เปลี่ยนเฉพาะค่า (path, duration, in/out, id ใหม่) — **ห้ามเดา key ที่ไม่เคยเห็นในแม่แบบ**
   - อัปเดต path ของสื่อทั้งหมดให้ชี้ไปที่ไฟล์ของคลิปนี้
5. เขียนทับทั้ง `draft_info.json` ที่รากและใน `Timelines/<UUID>/` ให้ตรงกัน

## ตรวจก่อนส่งมอบ (ทำทุกครั้งก่อนบอกผู้ใช้ว่าเปิด CapCut ได้)

```bash
python3 -c "import json; json.load(open('draft_info.json')); print('OK: valid JSON')"
```

ทำกับ**ทั้งสองไฟล์** (ที่รากและใน `Timelines/<UUID>/`) ถ้า parse ไม่ผ่านแม้แต่ไฟล์เดียว **ห้ามบอกผู้ใช้ว่าเสร็จแล้ว** ให้ rollback จาก backup ทันที

**สำรองไฟล์ก่อนแก้ทุกครั้ง** (แม้ CapCut จะมี `.bak` อยู่แล้วก็สำรองซ้ำเป็นของตัวเอง กันสับสนว่า `.bak` ไหนเป็นของใคร):
```bash
cp draft_info.json "draft_info.json.bak_$(date +%Y%m%d_%H%M%S)"
```

หลัง JSON ผ่านแล้ว เปิดดู `draft_cover.jpg` หรือ thumbnail ถ้ามี เพื่อ sanity-check เบื้องต้นว่าไม่ได้ผิดโครงสร้างจนภาพหาย (ถ้าเครื่องมือเอื้อให้เช็คได้)

## รายงานผลกลับผู้ใช้

สรุปเสมอ:
1. โปรเจกต์ต้นแบบที่ใช้โคลน + path โปรเจกต์ใหม่
2. จำนวนช็อตที่ใส่ / ความยาวรวม / ความเร็วที่ตั้ง
3. BGM ใส่แล้วยาวเท่าไร ตัด/ครอสเฟดกี่จุด
4. End credit ใส่แล้วหรือยัง (ถ้ายังไม่มี `citations.json` ให้บอกว่าขาดอะไร ยังใส่ end credit ไม่ได้)
5. Mid-roll marker ใส่ตรงไหนบ้าง
6. ผล JSON validation ทั้งสองไฟล์
7. **ย้ำชัดเจนว่าตอนนี้เปิด CapCut ได้แล้ว**

## หลังส่งมอบ

บันทึกปัญหา/ค่าที่เพิ่งเรียนรู้เกี่ยวกับ schema ต่อท้าย `.claude/memory/timecode.md` (หัวข้อ CapCut) เสมอ ถ้าเจอ key ใหม่ที่ไม่เคยรู้มาก่อน หรือพฤติกรรมแปลกของ autosave/versioning — จะได้ไม่ต้องเสียเวลาเรียนรู้ใหม่ตอนคลิปถัดไป
