# Analytics Review — อ่านตัวเลขให้ได้ข้อสรุปที่ไม่ต้องมาแก้ทีหลัง

สกิลนี้เกิดจากการที่รอบ 2026-09-23 **ตีความผิด 3 ครั้งติดกัน** จนวางแผนผิดทั้งชุดแล้วต้องมาแก้ในอีก 6 วันถัดมา ทั้งสามครั้งเป็นความผิดเชิงกระบวนการล้วน ๆ ไม่ใช่ความผิดของข้อมูล

> **กฎเหล็ก: ห้ามตีความตัวเลขใด ๆ ก่อนผ่านประตูตรวจในขั้นที่ 1 ครบทุกข้อ**

---

## ขั้นที่ 1 — ประตูตรวจข้อมูล (ทำก่อนเสมอ ห้ามข้าม)

### 1.1 เช็คว่าข้อมูลนิ่งแล้วหรือยัง — `watch hr ÷ avg view duration` ต้องเท่ากับ `views`

```python
# รันกับทุกแถวของรายงานที่มีทั้ง watch hours และ average view duration
implied = watch_hours * 3600 / avg_view_duration_seconds
ratio = implied / views          # ต้องใกล้ 1.00
```

- **ratio ≈ 1.0** → ข้อมูลนิ่ง ตีความได้
- **ratio ห่างจาก 1 มาก** → ข้อมูลยังประมวลผลไม่เสร็จ **ห้ามคำนวณ retention เองจาก watch hours**

**ข้อยกเว้นที่รู้แล้ว:** แถว **Browse features** คลาด ~2 เท่าเสมอ (เจอซ้ำทุกรอบ ไม่ใช่ lag — สันนิษฐานว่าหน้าฟีดนับ view จาก autoplay preview ที่ไม่เกิด watch time) → **ยึด watch hours เป็นความจริง อย่าใช้ "views" ของ Browse ไปคำนวณอะไรต่อ**

### 1.2 คลิปอายุต่ำกว่า 7 วัน — ห้ามสรุป retention จากการคำนวณเอง

ให้อ่านจากคอลัมน์ **`Average view duration`** หรือ **`Average percentage viewed`** ที่ YouTube รายงานตรง ๆ เท่านั้น

> เคสจริง: คลิป 007 อายุ 2 วัน คำนวณเองได้ **8.1%** (แย่ที่สุดในประวัติช่อง) ค่าจริงที่ YouTube รายงานคือ **37.6%** (เท่าคลิปที่ดีที่สุด) — เกือบสั่งเลิกใช้จังหวะจุดพลิกที่ใช้ได้ดี

### 1.3 ห้ามสรุปเรื่องระดับช่องจากรายงานของคลิปเดียว

> เคสจริง: วัดแหล่งที่มาจากคลิป 007 ตัวเดียว (อายุ 2 วัน) ได้ Suggested **0.5%** แล้วสรุปว่า "ช่องนี้ไม่มี Suggested เลย คอขวดคือสถาปัตยกรรมทราฟฟิก" — ความจริงระดับช่องคือ **53.4% ของ watch hours** คลิปใหม่ยังไม่มี Suggested เป็นเรื่องปกติเพราะ YouTube ต้องใช้เวลาหาว่าควรวางข้างคลิปไหน

**ถ้าจะพูดถึงระดับช่อง ต้องมีรายงานระดับช่องอยู่ในมือ** ถ้าไม่มี ให้บอกตรง ๆ ว่ายังสรุปไม่ได้ และขอเพิ่ม

### 1.4 ระบุกรอบเวลาของรายงานทุกครั้ง

รายงาน "90 วันล่าสุด" กับ "ช่วง 29 วัน" กับ "lifetime" เทียบกันตรง ๆ ไม่ได้ — เขียนกรอบเวลากำกับทุกตัวเลขที่อ้าง และเช็คว่าหน้าต่างเลื่อนไปหรือยังก่อนบอกว่า "เพิ่มขึ้น/ลดลง"

## ขั้นที่ 2 — เลือกโหมด

### โหมด A — Post-mortem รายคลิป (ทำที่ D+7 หลังอัปโหลด)

**ไฟล์ที่ต้องมี** (`Studio → เนื้อหา → คลิกคลิป → แท็บที่ระบุ → ส่งออก`):

| รายงาน | แท็บใน Studio | ใช้ตอบอะไร |
|---|---|---|
| **การคงผู้ชมไว้** | ความสนใจของผู้ชม | ฮุกพังตรงวินาทีไหน |
| **แหล่งที่มาของการเข้าชม** | เข้าถึงผู้ชม | Browse มาไหม · Suggested เริ่มหรือยัง |
| **เนื้อหา (คลิปเดี่ยว)** | ภาพรวม | CTR · impressions · subs |

**สิ่งที่ต้องทำ:**

1. **แมปกราฟ retention กลับเป็นประโยคในบท** — นี่คือหัวใจของโหมดนี้
   ```python
   # ตำแหน่ง % ของคลิปสุดท้าย -> วินาทีในไฟล์เสียงธรรมชาติ
   final_sec = pct/100 * duration_sec
   natural_sec = final_sec * 1.10        # คลิปเร่ง 1.10x ตาม decisions.md
   # แล้วเปิด work/<clip>/subtitles_clean.srt หาว่าวินาทีนั้นพูดอะไรอยู่
   ```
2. **ดูคอลัมน์ "Compared to other videos"** — บอกว่าจุดไหน**แย่กว่า/ดีกว่าคู่เทียบ** ซึ่งมีค่ากว่าตัวเลข retention ดิบ เพราะแยก "เนื้อหาไม่ดี" ออกจาก "ธรรมชาติของคลิปยาว" ได้
3. **เทียบผู้ชมใหม่ vs ผู้ชมที่กลับมา** — ถ้าผู้ชมเก่าอยู่ยาวแต่ผู้ชมใหม่หลุดเร็ว = **ปัญหาอยู่ที่ฮุก ไม่ใช่เนื้อหา**
4. เทียบกับเกณฑ์ที่ล็อกไว้ใน `channel.md`: CTR ≥3% · retention ≥35% · เสีย retention ใน 24 วินาทีแรกไม่เกิน ~20 จุด

### โหมด B — ทบทวนระดับช่อง (ทุก 4 สัปดาห์)

**ไฟล์ที่ต้องมี** (`Studio → ข้อมูลวิเคราะห์ → แท็บที่ระบุ → ส่งออก` ตั้งช่วง 90 วันล่าสุด):

| รายงาน | ใช้ตอบอะไร |
|---|---|
| **เนื้อหา (ทั้งช่อง)** | watch hours รวม · อัตราแปลง subs · ตารางเทียบทุกคลิป |
| **แหล่งที่มาของการเข้าชม (ทั้งช่อง)** | **Suggested CTR** ← ตัวชี้วัดหลัก |

**ไม่ต้องดึงบ่อย:** ประเภทอุปกรณ์ · ข้อมูลประชากร — เปลี่ยนช้ามาก ปีละครั้งพอ

## ขั้นที่ 3 — ผูกตัวเลขกับการตัดสินใจที่มีอยู่แล้ว

**ห้ามรายงานตัวเลขลอย ๆ** ทุกตัวเลขต้องบอกว่ากระทบการตัดสินใจข้อไหน:

| ตัวเลข | ผูกกับ | เส้นตัดสิน |
|---|---|---|
| **Suggested CTR** | คันโยกหลักของช่อง (`channel.md`) | **≥3%** (ตอนนี้ 1.51%) |
| **อัตราแปลง subs** = subs ÷ views | ทริกเกอร์ Shorts (`decisions.md`) | **< 0.84% = ต้องทำ Shorts** |
| **retention 24 วินาทีแรก** | กฎฮุก (`channel.md`) | เสียไม่เกิน ~20 จุด |
| **CTR ของคลิป** | สูตร thumbnail ที่ล็อกไว้ (`images.md`) | ≥3% |
| **วิวรายวันวันที่ 3 > วันแรก** | สัญญาณ "คลื่นที่สอง" | ถ้ามี = สูตรนั้นเวิร์ก ทำแนวเดียวกันต่อทันที |
| **คลิปก่อนหน้ายังขึ้นคลื่นไหม** | กฎระยะห่างการลงคลิป (`decisions.md`) | ถ้ายังขึ้น = เลื่อนคลิปถัดไป |

## ขั้นที่ 4 — เขียนผลลง memory

1. **ตัวเลขดิบทั้งหมด** → ต่อท้าย `archive/analytics-log.md` (ตารางรูปแบบเดียวกับรอบก่อนเสมอ เพื่อให้เทียบข้ามรอบได้)
2. **อัปเดตตารางตัวชี้วัดใน `channel.md`** หัวข้อ "โครงสร้างทราฟฟิกของช่อง" — เพิ่มคอลัมน์รอบใหม่ ไม่ใช่เขียนทับของเก่า (ต้องเห็นแนวโน้ม)
3. **ถ้าเจอบทเรียนที่ใช้ซ้ำได้** → เขียนสรุปสั้นในไฟล์หลักที่ตรงหัวข้อ ตามกฎใน `README.md`
4. **ถ้าข้อสรุปเดิมผิด** → เขียนว่า "ผิด ยกเลิก" พร้อมเหตุผลและตัวเลขใหม่ **ห้ามลบของเก่าเงียบ ๆ** เพราะรอบหน้าจะได้ไม่วนผิดซ้ำ

## สิ่งที่ห้ามทำ (สรุปจากความผิดพลาดจริง)

- ❌ คำนวณ retention เองจาก watch hours ของคลิปอายุ < 7 วัน
- ❌ สรุปเรื่องระดับช่องจากรายงานของคลิปเดียว
- ❌ ใช้ "views" ของแถว Browse features ไปคำนวณ/คาดการณ์อะไรต่อ
- ❌ เทียบตัวเลขข้ามรอบโดยไม่ดูว่ากรอบเวลาต่างกันไหม
- ❌ สรุปจากตัวอย่างขนาดเล็กโดยไม่เขียนกำกับ (เช่น ผู้ชมที่กลับมา ~18 คน)
- ❌ รายงานตัวเลขโดยไม่บอกว่ากระทบการตัดสินใจข้อไหน
